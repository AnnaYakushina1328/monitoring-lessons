# Мониторинг качества учебных занятий

Веб-платформа для планирования посещений учебных занятий, проведения экспертной оценки и анализа качества образовательного процесса.

Разработана для ГБПОУ города Москвы «Московский колледж бизнес-технологий».

## Возможности

- Учёт преподавателей и пользователей системы.
- Разграничение доступа по ролям.
- Планирование посещений учебных занятий.
- Оценивание по специализированным чек-листам.
- Поддержка очного и онлайн-форматов.
- Проверка соответствия формата занятия и типа чек-листа.
- Сохранение черновиков и завершённых оцениваний.
- Комментарии и результаты оценивания.
- Ознакомление преподавателей с результатами.
- Мониторинг, диагностика и аналитика.

## Типы чек-листов

| Код | Тип занятия |
| --- | --- |
| pd | Теоретическое занятие |
| lpz | Лабораторно-практическое занятие |
| oup | Общеобразовательное занятие |
| uppp | Учебная / производственная практика |
| attestation | Аттестация студентов |
| online | Онлайн-занятие |

Для онлайн-занятий используется чек-лист `online`. Для очных занятий доступны соответствующие офлайн-чек-листы.

## Быстрый локальный запуск

### Требования

- Git
- Docker
- Docker Compose

### 1. Получение проекта

```bash
git clone https://github.com/AnnaYakushina1328/monitoring-lessons.git
cd monitoring-lessons
```

### 2. Настройка окружения

Создать файл `.env` на основе `.env.example`.

Указать собственные значения:

- `DJANGO_SECRET_KEY`
- `POSTGRES_PASSWORD`
- `POSTGRES_DB`
- `POSTGRES_USER`
- `DJANGO_ALLOWED_HOSTS`

Для локального запуска можно использовать `DJANGO_DEBUG=1`.

Настоящий файл `.env` не должен попадать в Git.

### 3. Запуск контейнеров

```bash
docker compose up -d --build
```

### 4. Проверка приложения

```bash
docker compose exec web python manage.py check
docker compose exec web python manage.py migrate
```

По умолчанию приложение доступно по адресу:

http://localhost:8000

При первом запуске потребуется отдельно создать пользователей и подготовить справочники. Миграции создают структуру базы данных, но не гарантируют её заполнение.

### Запуск

Команда `docker compose down` без параметра `-v` не удаляет именованный том PostgreSQL.

### Просмотр журналов

```bash
docker compose logs -f web
```

### Применение миграций

```bash
docker compose exec web python manage.py migrate
```

### Проверка Django

```bash
docker compose exec web python manage.py check
```

## Хранение данных

Для хранения информации используется PostgreSQL.

В Docker Compose настроен именованный том `postgres_data`.

База содержит:

- учётные записи и роли;
- преподавателей;
- посещения занятий;
- шаблоны чек-листов;
- результаты оценивания;
- комментарии и подтверждения ознакомления.

**Важно:** не выполняйте `docker compose down -v` без понимания последствий. Эта команда удаляет тома проекта и может привести к потере данных.

Резервное копирование рабочей базы необходимо организовать отдельно.

## Развёртывание на сервере

Текущий `compose.yaml` предназначен для локальной разработки и использует Django `runserver`.

Для размещения приложения на публичном домене требуется production-конфигурация.

Администратору сервера необходимо:

1. Подготовить сервер с Docker и Docker Compose.
2. Настроить переменные окружения.
3. Задать уникальный секретный ключ Django.
4. Настроить PostgreSQL с постоянным хранилищем.
5. Использовать Gunicorn или аналогичный production-сервер вместо `runserver`.
6. Настроить Nginx или другой обратный прокси.
7. Подключить HTTPS-сертификат.
8. Указать домен в `DJANGO_ALLOWED_HOSTS`.
9. Настроить доверенные CSRF-источники.
10. Настроить выдачу статических файлов.
11. Установить `DJANGO_DEBUG=0`.
12. Настроить резервное копирование базы данных.
13. Выполнить проверку безопасности Django.
14. Проверить авторизацию и разграничение доступа.
15. Проверить создание посещений, заполнение чек-листов и отображение результатов.

Проверка конфигурации безопасности:

```bash
python manage.py check --deploy
```

Публиковать приложение в интернете через текущий `runserver` не рекомендуется.

## Перенос существующих данных

Исходный код на GitHub не содержит рабочую базу данных.

Если требуется перенести пользователей, преподавателей, посещения и результаты оценивания с локального компьютера на сервер, необходим отдельный защищённый перенос PostgreSQL.

Не следует публиковать дампы базы в открытом репозитории.

При переносе необходимо проверить:

- наличие всех преподавателей и пользователей;
- корректность ролей;
- целостность связей между преподавателями и учётными записями;
- наличие всех шести чек-листов;
- корректность существующих оцениваний;
- доступ преподавателей только к собственным результатам.

## Безопасность

Запрещено размещать в публичном репозитории:

- настоящий `.env`;
- пароли и секретные ключи;
- дампы рабочей базы данных;
- списки логинов и паролей;
- персональные данные преподавателей и студентов;
- временные диагностические выгрузки с реальными сведениями.

Доступ к административным функциям должен быть ограничен соответствующими ролями.
